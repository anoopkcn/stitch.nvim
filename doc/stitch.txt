1. INTRODUCTION                                      *stitch* *stitch-introduction*

Stitch gathers lines from many files into a single, grouped, editable
buffer — Neovim's take on Zed's multibuffers
<https://zed.dev/docs/multibuffers>.

Populate one view from a project search, LSP references, diagnostics, or the
current quickfix list, read it top-to-bottom, jump straight to any source
line, and edit stitch lines in place — `:w` writes every change back to its
source file at once.

Highlights:
  • Sources: project grep, LSP references, diagnostics, git/jj diff, quickfix
  • Quickfix-backed, so |:cdo| / |:cfdo| bulk edits work on the same set
  • Strict 1:1 editing with a source-divergence guard (never clobbers)
  • Per-stitch source context with interactive expand/collapse
  • Cross-file Treesitter syntax highlighting (each line in its own language)
  • Jump back to any source location with a single key

Use cases:
  • Read every hit of a search with a few lines of context around each
  • Review and fix all project diagnostics in one place
  • Edit every reference to a symbol without hopping between files
  • Turn a quickfix list into a readable, editable working set

==============================================================================
2. REQUIREMENTS                                      *stitch-requirements*

  • Neovim 0.11+ (developed against 0.12.x)
  • ripgrep <https://github.com/BurntSushi/ripgrep> (`rg`) on $PATH, for the
    grep source only. References, diagnostics, and quickfix sources need no
    external tools.

==============================================================================
3. QUICK START                                        *stitch-quickstart*

Stitch works out of the box. The |:Stitch| command is registered at
startup by plugin/stitch.lua, so |stitch.setup()| is optional — call it
only to override defaults.

With lazy.nvim: >
    {
      'stitch.nvim',
      opts = {}, -- calls require('stitch').setup()
    }
<
Try it: >
    :Stitch grep TODO          " every TODO in the project
    :Stitch references         " every reference to the symbol under cursor
    :Stitch diagnostics        " every project diagnostic
<
Inside the view: read down the buffer, press <CR> on any line to open its
source, edit lines in place and `:w` to save them back, or `q` to close.

4. COMMANDS                                              *stitch-commands*

All sources are reached through a single command with a subcommand: >
    :Stitch {grep|references|diagnostics|diff|qf|next|prev} [args]
<
                                                                  *:Stitch*
Tab-completion completes the subcommand name in the first argument position.
Each source funnels through the quickfix list (kept in sync so |:cdo| /
|:cfdo| operate on the same set) and then renders the stitch view on top.
If a source produces no results, a notification is shown and no view opens.

------------------------------------------------------------------------------
4.1 :Stitch grep                                          *:Stitch-grep*

Open a view from a project-wide ripgrep search. >
    :Stitch grep {pattern}
<
The remaining arguments are joined with spaces and passed to ripgrep as the
search pattern. If no pattern is given, you are prompted for one.

One stitch is created per matched line; the exact matched span(s) on each
line are highlighted with a translucent blue background (see |StitchMatch|).
Requires `rg` on $PATH.

Examples: >
    :Stitch grep TODO
    :Stitch grep function foo
    :Stitch grep \bstruct\s+\w+
<
------------------------------------------------------------------------------
4.2 :Stitch references                              *:Stitch-references*

Open a view of all references to the symbol under the cursor. >
    :Stitch references
<
Queries every attached LSP client that supports `textDocument/references`
(with `includeDeclaration = true`) and aggregates the locations. Requires a
language server attached to the current buffer.

------------------------------------------------------------------------------
4.3 :Stitch diagnostics                            *:Stitch-diagnostics*

Open a view of all project diagnostics. >
    :Stitch diagnostics
<
Collects every diagnostic from |vim.diagnostic.get()| across all buffers. Each
stitch shows the offending source line; the diagnostic message is shown as a
trailing annotation (see |StitchAnnotation|).

------------------------------------------------------------------------------
4.4 :Stitch diff                                          *:Stitch-diff*

Open a view of working-tree changes. >
    :Stitch diff [revspec]
<
Runs the version control system's diff and shows every added or modified line
as a stitch, grouped by file and editable like any other view (`:w` writes
your changes back). Both git and jujutsu are supported — they emit the same
git-format diff — and the VCS is auto-detected (a `.jj` directory means jj,
otherwise git).

With no argument it shows your current uncommitted changes (`git diff HEAD` /
`jj diff`). With a `revspec` it shows everything changed from that revision to
the working copy (`git diff {revspec}` / `jj diff --from {revspec}`): >
    :Stitch diff main      " everything on this branch vs main
    :Stitch diff @--        " (jj) changes since the grandparent
<
Note: only added and modified lines appear. The view shows current-file
content, so a change that *only removes* lines has nothing to display.

------------------------------------------------------------------------------
4.5 :Stitch qf                                              *:Stitch-qf*

Build a view from the current quickfix list. >
    :Stitch qf
<
Uses the quickfix list exactly as it stands — populate it however you like
(|:grep|, |:vimgrep|, |:cexpr|, another plugin) and turn it into a stitch
view. Unlike the other sources, this does not replace the quickfix list. If
the list is empty, a notification is shown.

------------------------------------------------------------------------------
4.6 :Stitch next / :Stitch prev              *:Stitch-next* *:Stitch-prev*

Jump to the next/previous stitch: load its source buffer and land the cursor
on the match's line and column. >
    :Stitch next
    :Stitch prev
<
Both work from anywhere — the view window or a source window. They walk the
stitches of the view visible in the current tabpage (the most recently used
one when several are showing), wrapping past either end. The view's cursor
advances with each step, so the walk continues from wherever you last were
in the view, and moving the view cursor by hand re-positions the walk.

Unlike |:cnext| over the same set, these follow the live view: anchors move
with edits, so the jump targets stay correct after the sources (or the view)
have been edited. If no view is visible, a notification is shown.

==============================================================================
5. THE VIEW                                                  *stitch-view*

The view is a dedicated, editable scratch buffer (filetype `stitch`,
buftype `acwrite`). It is opened where |stitch-window| says.

Layout:
  • Stitches are grouped by file under a full-width header bar showing the
    `{relative path}`, aligned to the left edge.
  • Each line shows its source line number in the left gutter.
  • Match lines carry a brighter line number than surrounding context lines.
  • The matched span(s) get a translucent blue background on top of syntax
    highlighting.
  • Diagnostic (or other quickfix) messages appear as a trailing annotation.
  • When context hides part of a file, a `⋮` divider marks the gap (the jump
    in line numbers shows its size).

Each real line maps 1:1 to one source line. There is one stitch per source
line even if a line has several matches — all their spans are highlighted.
Files that cannot be read (or are empty) are skipped.

==============================================================================
6. MAPPINGS                                              *stitch-mappings*

These buffer-local mappings are active inside the view. The keys are
configurable via |stitch-keys|; set one to a false-y value to disable it.

                                                            *stitch_<CR>*
<CR>        Open the source file of the line under the cursor, at its line and
            column. Reuses an existing window in the tab if there is one,
            otherwise opens a vertical split.

                                                              *stitch_q*
q           Close the view (closes the window, or deletes the buffer if it is
            the last window in the tab).

                                                              *stitch_+*
+           Expand: show more context around the stitch under the cursor.
            Adds |stitch-context-step| lines, or a count: `10+` adds 10.

                                                              *stitch_-*
-           Collapse: show less context around the stitch under the cursor
            (floor of 0). Count-aware, like `+`.

The view does not remap editing keys: `gc`/`gcc`, `dd`, `J`, `o`, `p` and the
rest are stock Neovim. See |stitch-editing| for how those edits are written
back, and the |stitch-editing| "Commenting" note for `gc` language handling.

See |stitch-context-lines| for how expand/collapse behave.

==============================================================================
7. EDITING & WRITE-BACK                                   *stitch-editing*

Edit the buffer with any native command — change text, `dd`, `J`, `o`, paste,
split a line into several, `gcc` to comment — then `:w`. Changes are written
back to the correct source files and all touched files are saved together.
There are no plugin-specific editing maps.

On `:w` the buffer is diffed against the text painted when the view was opened
(or last saved). Each diff hunk is mapped back to its source range via the
per-row anchors and rewritten with |nvim_buf_set_lines|, so in-place edits,
line *deletion*, *insertion*, and *multi-line* changes are all written back —
the diff reconciles whatever state the buffer ends up in, with no
command-specific handling.

Two guarantees bound what is written:

  • If a source line changed underneath you since the view opened, that edit is
    flagged inline with `‹ source changed — not written ›`
    (see |StitchDivergent|) and skipped — never clobbered.
  • A hunk that cannot be mapped to a single source range — it spans two files,
    or a structural change straddles a block boundary — is flagged
    `‹ cannot map edit (spans files/blocks) — not written ›` and skipped rather
    than guessed at.

A clean save re-renders the view (fresh line numbers; this clears undo). A save
with skips keeps the buffer and its inline flags so you can resolve the conflict
and save again.

After `:w` a summary is shown, e.g.: >
    stitches: wrote 3 edit(s) in 2 file(s)
<
with any skipped counts appended.

Note: write-back goes through each source buffer and writes it, so saving the
stitch buffer behaves like saving those files directly — it also persists
any other unsaved changes in them and triggers their |BufWritePre| /
|BufWritePost| autocommands. If you use format-on-save, every touched file is
formatted on `:w`.

Commenting~

`gc`/`gcc` are stock Neovim commenting. Because the view aggregates many files,
'commentstring' is kept in sync with the source file under the cursor, so
commenting uses each stitch's own language (Lua with `--`, Python with `#`,
...). A single-line or single-file comment is exact. A multi-line `gc` spanning
*different* languages uses the cursor line's syntax — Neovim's built-in
commenting resolves one 'commentstring' per invocation, a limitation no buffer
setting can lift.

==============================================================================
8. BULK EDITS                                          *stitch-bulk-edits*

The view is backed by the quickfix list, so Neovim's built-in cross-file edit
commands operate on the same set with no extra plugin code: >
    :cdo s/old/new/ | update     " substitute across every stitch's line
    :cfdo %s/old/new/g | update   " substitute across every file in the list
<
This complements in-view editing: edit stitches directly for hand changes
(including deletion, insertion, and multi-line edits), or use `:cdo`/`:cfdo` for
a uniform substitution across every entry in one pass.

Note: the grep, references, and diagnostics sources replace the quickfix list
when they run; the |:Stitch-qf| source reads it without replacing it.

==============================================================================
9. CONTEXT LINES                                     *stitch-context-lines*

Set |stitch-context| to N to show N source lines above and below every
match. Context lines are dimmer than match lines but are fully editable,
jumpable, and highlighted just like a match — so `context` is also a quick
way to edit a few lines around each hit without leaving the view.

Within a file, overlapping or adjacent context blocks are merged into one,
and a gap between two blocks of the same file is shown as a `⋮` divider (the
jump in line numbers indicates how many lines it spans).

`context` only sets the *initial* extent of each block. From then on the
visible range is stable content, not a radius around the match: saving an
inserted line grows the block by that line (nothing else slides out of
view), deleting a line shrinks it (no previously-hidden line slides in),
and deleting the gap between two blocks joins them.

Interactive expand/collapse~

Press `+` / `-` (see |stitch-mappings|) to widen or narrow the block under
the cursor by |stitch-context-step| lines per end, or a count: `10+`.
Expanding far enough merges it with the neighbouring block. Collapsing stops
at the block's matches — match lines never vanish from the view, and the
lines between two matches of a merged block stay visible. A block whose
match lines were edited away can be collapsed until it disappears.

Because expand/collapse re-lays-out the anchored lines, it resets the buffer's
undo history:
  • Pending edits to existing stitch lines are preserved (and still save).
  • You cannot `u` across an expand/collapse.
  • Brand-new lines you typed into the view (which are not anchored to a
    source line and would not be written by `:w` anyway) are dropped.

==============================================================================
10. HIGHLIGHTING                                     *stitch-highlighting*

Syntax highlighting~

Each stitch is syntax-highlighted with its *source file's* Treesitter
grammar, so a view mixing Lua, Python, and Markdown shows each line in the
right colours. Each contiguous block is parsed in its own language (the grammar
is derived from the filename — no LSP is started just to colour a stitch), so
edited and newly-inserted lines are highlighted live from the buffer's own
text. Files whose language has no Treesitter parser render uncoloured. Disable
with |stitch-highlight| = `false`.

Match highlighting~

The matched text itself is marked on top of syntax with a translucent blue
background (|StitchMatch|):
  • grep: the exact search span(s) reported by `rg --json`.
  • references / diagnostics: the symbol or diagnostic range (single-line
    ranges only).

11. CONFIGURATION                                  *stitch-configuration*

Pass options to |stitch.setup()| (or to lazy.nvim's `opts`). Defaults: >
    require('stitch').setup({
      window = 'split',   -- 'split' | 'vsplit' | 'tab' | 'current'
      highlight = true,   -- project Treesitter highlighting onto stitches
      context = 1,        -- source context lines above/below each match
      context_step = 1,   -- lines added/removed per +/- press
      max_results = 2000, -- cap on grep results (false disables)
      keys = {
        jump = '<CR>',
        close = 'q',
        expand = '+',
        collapse = '-',
      },
    })
<
------------------------------------------------------------------------------
                                                          *stitch-window*
window~
    Type: string
    Default: "split"

Where to open the stitch view. One of:
    "split"     horizontal split below (botright)
    "vsplit"    vertical split on the right (botright)
    "tab"       a new tab page
    "current"   reuse the current window

------------------------------------------------------------------------------
                                                       *stitch-highlight*
highlight~
    Type: boolean
    Default: true

Project each source file's Treesitter syntax highlighting onto its stitch
lines. Set to `false` to render stitches uncoloured. The match-span
highlight (|StitchMatch|) is independent of this setting.

------------------------------------------------------------------------------
                                                         *stitch-context*
context~
    Type: integer
    Default: 1

Number of source lines initially shown above and below each match. 0 shows
just the match line. Context lines are editable, jumpable, and highlighted
like matches. After opening, each block's visible range is stable content
that follows your edits rather than a fixed radius — see
|stitch-context-lines|.

------------------------------------------------------------------------------
                                                    *stitch-context-step*
context_step~
    Type: integer
    Default: 1

Lines added or removed per `+` / `-` press. A count on the mapping overrides
it for that press (e.g. `10+` adds 10 lines regardless of this value).

------------------------------------------------------------------------------
                                                     *stitch-max-results*
max_results~
    Type: integer or false
    Default: 2000

Cap on the number of |:Stitch| grep results. A broad pattern in a large
repository would otherwise build an enormous view (and read every matched
file) in one UI-blocking tick. A notification tells you when results were
truncated. Set to `false` to disable the cap.

------------------------------------------------------------------------------
                                                            *stitch-keys*
keys~
    Type: table
    Default: { jump = '<CR>', close = 'q', expand = '+', collapse = '-' }

Buffer-local mappings inside the view. See |stitch-mappings| for what each
does. Set a field to a false-y value to disable that mapping: >
    require('stitch').setup({
      keys = {
        jump = '<CR>',
        close = '<Esc>',   -- close with Esc instead of q
        expand = false,    -- disable expand
        collapse = false,  -- disable collapse
      },
    })
<

12. HIGHLIGHT GROUPS                             *stitch-highlight-groups*

All groups are defined with `default = true`, so any link you set before or
after setup wins. Override them with |:highlight| (or `nvim_set_hl`).

A file header is a full-width background bar showing the path, `{dir}{name}`,
dimmed onto it. The path starts at the left edge: its leading characters are drawn
in the header row's gutter (which carries no line number), the rest in the bar.

                                                        *StitchHeaderBg*
StitchHeaderBg~
    Background bar behind a file header (and its gutter cell). Default: the
    background of |hl-CursorLine| (falling back to |hl-Visual|). The header
    groups below are resolved against this background, re-resolved on
    |ColorScheme|.

                                                       *StitchHeaderDir*
StitchHeaderDir~
    The dimmed directory part of a file header. Default: |hl-Comment|
    foreground on the |StitchHeaderBg| background.

                                                      *StitchHeaderName*
StitchHeaderName~
    The file name in a file header. Default: |hl-Comment| foreground on the
    |StitchHeaderBg| background (dimmed, matching |StitchHeaderDir|).

                                                            *StitchLnum*
StitchLnum~
    Inline source line number on a match line. Default: links to |hl-LineNr|.

                                                     *StitchContextLnum*
StitchContextLnum~
    Inline source line number on a context line. Default: |hl-NonText|.

                                                           *StitchMatch*
StitchMatch~
    The matched span on a line, drawn over syntax. Default: a translucent
    blue background — blue (`#61afef`) blended into the editor background at
    25% weight, since buffer-text highlights have no real alpha. Re-resolved
    on |ColorScheme|.

                                                      *StitchAnnotation*
StitchAnnotation~
    Trailing annotation (e.g. a diagnostic message). Default: |hl-Comment|.

                                                       *StitchSeparator*
StitchSeparator~
    The `⋮` block divider and the blank spacing between files.
    Default: |hl-NonText|.

                                                       *StitchDivergent*
StitchDivergent~
    The inline `‹ source changed — not written ›` flag on a skipped stitch.
    Default: links to |hl-WarningMsg|.

13. FUNCTIONS                                          *stitch-functions*

The module exposes a small Lua API. Each source function is equivalent to the
matching |:Stitch| subcommand.

------------------------------------------------------------------------------
                                                         *stitch.setup()*
stitch.setup({opts})
    Optional. Override configuration defaults. The |:Stitch| command is
    registered at startup regardless, so the plugin works without calling
    this.

    Parameters: ~
        {opts}  (table|nil) Options (see |stitch-configuration|).

    Example: >
        require('stitch').setup({ window = 'vsplit', context = 2 })
<
------------------------------------------------------------------------------
                                                          *stitch.grep()*
stitch.grep({pattern})
    Open a view from a ripgrep search. Equivalent to |:Stitch-grep|.

    Parameters: ~
        {pattern}  (string|nil) Search pattern. Prompts if nil or empty.

    Example: >
        require('stitch').grep('TODO')
<
------------------------------------------------------------------------------
                                                    *stitch.references()*
stitch.references()
    Open a view of all references to the symbol under the cursor. Equivalent
    to |:Stitch-references|.

    Example: >
        require('stitch').references()
<
------------------------------------------------------------------------------
                                                   *stitch.diagnostics()*
stitch.diagnostics()
    Open a view of all project diagnostics. Equivalent to
    |:Stitch-diagnostics|.

    Example: >
        require('stitch').diagnostics()
<
------------------------------------------------------------------------------
                                                    *stitch.from_qflist()*
stitch.from_qflist()

        require('stitch').from_qflist()

------------------------------------------------------------------------------
                                          *stitch.next()* *stitch.prev()*
stitch.next()

<

14. NOT IN SCOPE                                     *stitch-not-in-scope*

  • Multi-cursor editing across files. Zed's headline "wide refactor" mechanism
    has no Neovim equivalent and is intentionally not implemented — use
    |stitch-bulk-edits| (|:cdo| / |:cfdo|) over the quickfix list instead.
  • Inserting or deleting lines *inside* a stitch (structural in-view edits).
    Edits are strictly 1:1; see |stitch-editing|.
